# Memory candidates (private workspace)

`@lazy-harness/monitoring-module-memory` proposes potentially durable **project** facts/decisions for later independent host review. It never writes canonical memory, injects parent context, steers, blocks tools, approves claims, or calls a model/network service. Durability describes the intended claim lifetime, not storage. Semantic usefulness is **P5 and unmeasured**.

## Public API and composition

- `MEMORY_MODULE_ID = 'review.memory-candidate'`, `memoryQuestion`, `memoryDeclaration`, `memoryBinding`.
- `createMemoryRegistration({ stage?, reviewSink? })`: omitted stage is `observe`; explicit `shadow` requires the existing core `memory.review-sink` protocol-1 volatile binding. Author ceiling is `shadow`; `active` (even explicit) rejects. No job costs/model bindings or actions; template/read-only/candidate/per-subject/report-never only. Configured core preflight requires the declared sink before factories, even in observe; direct observe registration can omit it.
- `createMemoryMonitor({ stage?, reviewSink?, source, limits?, sinkTimeoutMs? })`: module-owned runtime composition. `onOpportunity(frame, mode, signal?)` consumes an admitted finalized frame and an externally supplied typed `run | skip | defer` judgement. It does not perform judgement/model calls. `close()` is terminal, aborts pending intent; `idle()` awaits bounded composition settlement; `getStatus()` exposes counts, not bodies. No report callback or read-ledger binding exists.
- `MemorySource.capture(frame)` returns a strict `MemoryInput` sidecar (validated by `parseMemoryInput`). `isCurrent(input, frame)` must reacquire scope, source versions, attribution and grants, before preparation/handoff and after receipt. The host owns this authority; kind/role/tool success alone cannot establish it. No real source adapter is implemented here.
- `prepareMemoryCandidate(input, predecessorCandidateId?)`: pure deterministic exact-span worker, **0 generative calls**, no I/O or sink callback. It copies only admitted source spans, never paraphrases. Module composition hands its known validated output to the sink only after runtime-confirmed preparation and fresh checks. The runtime's `JobOutcome` API is unchanged.
- `MEMORY_KINDS`, `MemoryEvidence`, `MemoryInput`, `MemoryResult`, `MEMORY_LIMITS`, `MemoryLimits` are exported types/data. Confidence is absent, not an approval/usefulness oracle.

Hosts bind this package explicitly. There is no automatic module activation or registry discovery. Core owns neutral envelopes/validation/fake conformance; the Pi adapter owns lifecycle generations only; the separate lazy-harness repository owns real sources, attestation, policy/catalog data and review UI. Do not connect this sink to parent report delivery, a read ledger, persistence or automatic knowledge ingestion.

## Material, judgement, envelope

Watch only `user.message`, `assistant.message`, `turn.end`, `user.steer`. Finalized user content requires original-user attribution. Assistant-only claims defer. Turn-end copies resolve to the attested original source; steering fences prior pending intent without reopening consumed keys. Control frames (compaction, branch/session replacement/navigation, shutdown) terminally fence the open monitor; the host closes its sink, waits for old composition, and creates a new scope without carry. A new `session_start` also closes an already-open scope.

Kinds are `user-text`, `assistant-text`, bounded `conversation-history`, optional `project-policy`, optional `prior-candidate`. This initial worker permits supporting original-user or trusted approved-record evidence only; prior-candidate bodies cannot establish truth/approval. No implicit compaction/reduction need is requested. Host-supplied normalized subject/project/applicability and original evidence identities are mandatory; no semantic key inference.

Run: useful beyond this turn, exact complete admitted support, clear project/subject, original decision attribution or trusted approved record, nonduplicate. Skip: transient status/request/test output, acknowledgement, general knowledge, no lasting claim, unchanged duplicate. Defer: plausible lasting claim with conflict, missing scope/permission/revision, partial evidence, unresolved association, assistant-only support or alleged approval. The typed judgement cannot override deterministic gates. Conflict classification and semantic durability remain host/judgement responsibilities, not text heuristics.

The core `memory-candidate/v1` sink envelope is extended with optional strict project/provenance/preparation/link metadata (legacy minimal envelopes remain valid). This module always includes project/applicability, scope generations, exact claim/kind/language, evidence IDs/versions/namespace/actor/event/cursor/attestation/source+grant revisions, UTF-16 span locators and canonical span hashes, subject/dedupe identity, checked provenance, noncontested markers and fingerprints/template version. Hashes establish identity/integrity, not authority or anonymization. Unknown fields reject. Review receipts stay separate; the module never self-asserts sink acceptance.

## Protection, bounds, receipts and retention

One candidate per opportunity. Defaults: claim 2 KiB UTF-8, 8 refs, candidate 16 KiB serialized JSON; 128 body reservations/1 MiB bodies, 4,096 combined dedupe/source-protection keys/1 MiB metadata per open scope; 1 active composition/16 queued opportunities. Hosts may only tighten caps. Body counts conservatively include refused/unknown/discarded preparations, not just retained sink bodies; no capacity renewal through diagnostic pruning or sink refusal. Input frames/sidecars have separate bounded core admission (128 KiB JSON; each source body at most 8,192 characters). Caps are unmeasured design limits, not performance guarantees.

Dedupe uses scope/project/normalized subject, exact claim and sorted original evidence revision/span identities, not the current observation event. Unchanged finalization/turn-end copies suppress. A changed supported revision gets a distinct linked candidate. Changed bytes/attribution under an unchanged source revision defer. Host-identified conflicts defer; there is no contested-candidate workflow. No cross-scope or restart dedupe. Keys reserve before dispatch/handoff and never evict/retry while scope is open, including unknown acceptance. A link denotes a previous proposal, not approved truth.

Only host-owned `ReviewSinkPort.enqueue` receives candidates. Matching validated `accepted-volatile` means retained for private review in this process, **not viewed, approved, persisted, read by the parent, or provider-delivered**. Refused/unknown/malformed/mismatched/thrown receipts cannot count as accepted. Sink timeout (default 2 seconds, configurable 1–30,000 ms) aborts and leaves uncertain protection consumed. The host must honor signals and perform its own atomic freshness checks at acceptance; late completions cannot restore module acceptance after close/steering/revocation. There is no automatic retry/reconciliation or durable exactly-once claim.

Bodies live only in the host sink for the current scope. The module retains count/key metadata and active work only. Host revocation/lifecycle wiring must close both monitor and sink and clear volatile bodies. No disk backend, timer-based export, restart recovery or R7 persistence. Host-provided callbacks/sinks are trusted protocol implementations, not sandboxed by this package.

## Scripted evaluation and limits

`packages/eval` exports `createMemoryEvalModule` and registers the shipped binding in its shared `replay` runner. The old P4 placeholder is now named `synthetic.memory-candidate`; it cannot impersonate the shipped module or reuse its sink need. Only explicit invented sidecars and scripted typed decisions are consumed; no model backend is called on this path. Matching fake-sink receipts, not the script's delivery flag alone, determine `received`; private acceptance never populates parent enqueue/delivery arrays. Candidate/receipt identities are hash-bound in completion trace content. Observe has no jobs/candidates/receipts. Labels are parsed/scored separately and have no runtime input parameter.

Opportunity unit: `(moduleId, eligible finalized frame)` at the four watched points, regardless of admission; linked multi-frame subjects remain separate opportunities. First supported enduring attributable scoped claim is positive, unchanged copies negative, supported changed revision potentially positive, unresolved contradiction/attribution unresolved. Transient/general material is negative; denied material is safety-negative, not a semantic positive. Missing admission/cancellation/technical failures remain in oracle denominators. Tests use invented normative assertions only, not experiment results or holdout quality gold. Shared score reports proposal/receipt mechanics; it does **not** establish independent semantic content usefulness, calibrated truth, judgement accuracy or useful-received P5 quality.

Real host sources/review UI, natural-session usefulness, provider receipt, resource performance, privacy under real data, independent P5 oracle and restart durability remain **UNVERIFIED**. No real sessions, registry records, model calls, experiments or deployment are part of this implementation.
