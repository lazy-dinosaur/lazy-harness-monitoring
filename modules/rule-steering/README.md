## Purpose and API

- `RULE_STEERING_MODULE_ID = 'rules.steer'`, `RULE_VERIFIER_CAP = 8`.
- `ruleSteeringQuestion` and `ruleSteeringVerifyQuestion`: current-event-only runtime questions, unchanged from the inspected module. Earlier items are context; exceptions must be visible, missing deciding values defer. Gold/adjudication text is deliberately not imported.
- `ruleSteeringDeclaration`, `ruleSteeringBinding`: validated/hash-addressed public-core binding, empty settings only. Watches named `tool.before` and finalized `assistant.message` (not user/custom messages or provisional streams), two turns of bounded history; needs `policy.registry` and `judge.view`; one read-only `jev-select` job `remind`. The form name is a protocol identifier, not a provider dependency.
- `createRuleSteeringRegistration()`: runtime registration with **stage observe**. The shipped declaration's `maxStage` is also **observe**, so configured hosts cannot promote it. The low-level runtime is trusted and can bypass declaration ceilings: do not manually register it as active. Observe judges/traces only; no job, verification or report is run.
- `policyReferences(registry: PolicyRegistry)`: pure projection of an **explicit authoritative, versioned, ADMITTED** registry supplied by the caller. No default argument, path, file loading, discovery or authority inference. The host owns admission/allowlisting; a type or kind alone does not prove authority. `PolicyRegistry` has `id`, `version`, and `policies`; each policy requires `id`, `version`, `title`, with optional `summary`, `scope`, `exceptions`. Unknown fields, absent versions, duplicate IDs, oversized/malformed data reject. Limits: 64 policies, 16 exceptions/policy, 4096 chars per text field, 8192 chars per projected body, plus core bounded JSON limits. Unsupported external registry formats require an explicit host adapter, not a silent fallback.
- `PolicyReference`: `policy:<id>`, kind `policy`, SHA-256-derived 16-hex version over registry identity/version and the entire policy. Text includes declared registry/rule versions, scope and every exception. Any deciding text/version change changes the reference version. Reports quote ID, derived version and complete admitted text.
- `RuleVerifier(task, signal)` and `ruleVerificationTask(view, ruleId)`: the host supplies a typed verifier. The immutable task retains the exact current IDs/context but only the one target policy, sets `verifyReferenceId`, and disables per-item reference questions. Invalid/missing current IDs, rule, view identity or selected text/version mismatch reject. No engine-level second judgement.
- `createRuleSteeringHandlers(verify?, maxLedgerKeys = 4096)`: isolated handlers per host lifetime. Inject the verifier explicitly to prepare anything. Compatibility `ruleSteeringHandlers` is inert/fail-closed, **not** the legacy unverified template fallback. Missing turn/view/verifier/lease rejects; only `run` verifications survive. Undefined, failed, cancelled, skip or defer results do not produce reminders. A partial batch may remind only independently confirmed rules.

## Host composition and limits

Use only public core exports. The host must explicitly bind the module ID/version, a judge profile (`default-judge` for the job cost declaration), settings, needs adapters, granted kinds, handlers, a worker port (e.g. core `createHandlerWorkerPort`) and an approved `ApprovedBudgetGate` window. For `prepareMonitoringBindings`, advertise both underlying events (`tool_call`, `message_end`) and explicitly map `monitoring.rule-reminder` through host `internalActions`; it is not a new `HostAction`, nor permission to block tools. Named triggers exclude provisional/user messages. Public binding validation rejects unsupported events/actions.

For current-event isolation, configure `createRealtimeSelectionPipeline` with `frameBoundedMaterial: true`, `currentInPayload: true`; supply only admitted rules to its material window. Map packet `view`, selected materials, host session ID and explicit host turn into the runtime trigger. Never infer a turn from the event ID. The host must forward frame order strictly, advance intent on approved user steer, update rule versions on changes and check `offer.isCurrent()` at report enqueue and delivery. The module alone cannot attest source freshness, host authority or final provider input. Tests explicitly exercise this host contract.

The runtime's whole-selection idempotency key is supplemented by a bounded session/turn/**individual rule ID** ledger, including in-flight reservations. Overlapping selections cannot repeat a rule. Different versions of one rule are still suppressed for that turn. New session/turn keys are independent; absent/invalid turns fail closed. Failed/non-run verification releases its per-rule reservation, but runtime attempted keys remain terminal. Prepared keys remain consumed even after denied delivery. Ledger saturation refuses new work without eviction; construct new handlers at a deliberate host lifecycle boundary. No restart persistence or automatic reset is claimed.

Enqueue receipts must match `monitoringReportId`. A later controlled host receipt has `kind: 'hook-boundary'`, `boundary: 'context_with_system'`; enqueue/prepared is not delivery, and a hook receipt is not proof of final provider input. Active-stage integration tests are trusted **invented mechanical probes only**, not permission to activate the shipped binding.

### Verifier cost and offline evaluation

A run judgement selecting N rules can cost **1 primary judgement + N verifier calls**, with **N <= 8**, thus **9 logical classifier calls maximum** (0 generative worker calls). More than 8 selected rules explicitly returns `verifier_cap_exceeded`, never silent truncation. Budget preflight consumes the full pending batch before dispatch, so a too-small/missing lease makes zero verifier calls; the runtime reserves the full declared cap 8 before a job. No retries/fallbacks. Actual physical HTTP, provider batching, wall time and USD are **UNVERIFIED**; callbacks can hide physical attempts, so future provider adapters must meter those separately. Default observe uses only the primary judge.

`packages/eval` exports `createRuleSteeringEvalModule(references, stage = 'observe')`. It registers the real questions, grants and job, not `review.rules`. An explicit **scripted-only shadow probe** changes only the declaration ceiling to shadow; all other declaration fields/grants must match, report is `never`, active is rejected. This probe is not the production declaration or activation. Replay maps strict host frames directly, takes turn only from `turn_start`, and passes the original judge view to the real handler. Optional per-output `verifications: [{ruleId, mode}]` supply hand-scripted results (`run/skip/defer/failed`); omitted answers fail closed. Worker failure/cancel controls remain independent. `work.verification` records task/result identities with normal consent/redaction handling; `cost.verifierCalls` counts calls, `cost.judgeCalls` includes primary + verifier calls, and stub USD includes both. These are logical/stub estimates, not measurements. Byte-identical repeated replay is tested. Old v1 trace artifacts without these added accounting fields need regeneration; they are not silently trusted.
