## Reading the matrix

- `verified`: **only the explicitly scoped behavior** is exercised by a test in the currently passing 164-test invocation. A source declaration or test title in pending files is not enough.
- `gap`: an intended requirement has incomplete implementation, integration, or proof. Future probes/artifact names below are **proposed**, not existing files or run receipts; pending work is **UNVERIFIED**.
- `unsupported`: not implemented/supported in the reviewed surface, not permission to implement it.
- `n/a`: deliberately outside this gate. No whole-stage acceptance is inferred from a verified subclaim.
- Owner values are `core`, `hosts/pi`, planned `hosts/pi-fabric`, `module`, `eval`; `+` denotes joint ownership and the leftmost owner coordinates the proof. Owner is a repository layer, not an assignment to a person.

Path aliases (expand these literally to get exact `file:symbol` / `file:test title` citations):

- `S/` = `packages/core/src/sdk/`; `E/` = `packages/core/src/engine/`; `H/` = `packages/core/src/host/`.
- `P/` = `hosts/pi/src/`; `C/` = `packages/core/test/`; `PT/` = `hosts/pi/test/`.
- Test references quote exact case titles; parameterized `%s` titles are identified as such. Tests in `PT/pending-from-core/` are never counted as verified.

## P0 exit interpretation

Every intended R1–R10 / P1–P7 claim above has a layer owner and a measurable test/probe/artifact path. This satisfies the **inventory/proof-path portion** of the P0 exit criterion; D1 connector placement is decided and D2 numbers are provisionally adopted for P1 (user 2026-11-09), requiring user re-confirmation before any P5 measurement. This does not assert measured acceptance, runnable scenario sufficiency, or later-phase completion. Unsupported/deferred scope and decisions requiring user approval remain explicit in the index.
